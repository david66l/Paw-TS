### 关键量化结论

- **head**：3-5 条消息或 2-4K tokens（≤10%×L）；首因收益集中在最前 10%
- **tail**：随 L 收缩（≤16K 用 20%，16-64K 用 15%，>64K 用 10%）+ 绝对保底（最近 20-40 条或 8-16K tokens，取小者）+ 当前工具调用上下文永不压缩
- **取回预算**：总 16K 字符 + 单次 8K（超长头尾窗口/分块游标）+ LRU 回退 + 每步 ≤2 次；召回预算倒 U 型（16k/8k 最优）
- **压缩触发**：0.8×预算软启动（VISTA ρ=0.8）；触发后单次批量清扫（TokenPilot B=3），不做逐轮微调
- **门控**：节省 20-80%（对齐 SWE-MeM 过滤线）；逐字块精确匹配（非关键词）
- **成本记账**：output token 60× cache-hit（TokenPilot 定价）——预算按成本而非 token 分配

## 一、原始方案（现状全景）

### 1.1 架构：三层压缩 + 预算池

```
每轮 executeTurn（orchestrator.ts:1325 起）:

  L1 事后裁剪（pruner.ts）
    单个工具结果 > 50,000 字符  → 落盘 .paw/tool-results/，上下文换预览
    工具结果数量 > 5             → 更旧的落盘
    保护工具：skill / web_fetch / web_search / todo_write 永不裁剪

  L2 LLM 摘要（compactor.ts + compression-agent.ts）
    触发：estimatedTokens > 0.7 × contextWindow − 10,000
    边界：head 前 2 条逐字保留 + tail 最后 20% token 保留 + middle 压缩
    摘要：一次辅助模型调用，输出 8 个 markdown 章节
    质量门控：3 章节非空 + 节省 ≥ 15%；连续失败 2 次跳过，3 次熔断
    增量：有 previous summary 时走追加更新模式

  L3 硬驱逐（policy.ts，每次消息追加后自动）
    阈值：40 条消息 / 80,000 字符
    优先级：约束 120 > 工具结果 95 > system 90 > user 80 > assistant 60/40
    保护：首条 user、约束关键词消息、最近 3 回合、最后一条；降级 3→0

  Budget 池（budget.ts，比例制）
    ≤500K 窗口：system 12% / tools 8% / history 75% / reserve 5%
    >500K 窗口：system 8% / tools 7% / history 85% / reserve 5%

  上下文构成：system prompt + memory section + context package（task+代码）
              + 最近轮次（assistant 文本 + 工具结果）
```

### 1.2 执行时序

```
工具执行 → addToolResults(完整 payload) → 本轮结束
        → 下一轮: L1 prune → 预算测量 → L2 compact(超阈值) → 调模型
```

## 二、问题诊断（8 个）

### 2.1 执行层（3 个，先修）

**问题 1：工具结果注入前不截断**（日志 04）——完整 payload 原样注入，L1 下一轮才执行，存在整轮超载窗口期；单条 500KB 击穿上下文。

**问题 2：token 估算 4 套口径**（日志 02）——cl100k 主路径 / chars÷4 pruner / ascii÷4+中文÷1.5 memory / chars÷4 budget；实测 cl100k 对 DeepSeek 低估 37%。

**问题 3：L2 阈值双口径**——`budget.ts:112`（historyBudget×0.7−10k）vs `compactor.ts:88`（contextWindow×0.7−10k）相差近 2 倍。

### 2.2 结构性缺口（5 个）

**缺口 4：head 保护是位置驱动，不是内容驱动**——用户需求/约束/变更在第 5+ 条消息会被压缩进 middle。论文：Plans Don't Persist（中间计划被驱逐 −34.7pp）、Governance Decay（中间约束被擦除 38% 违规）、Lost in the Middle（中间利用最差）。

**缺口 5：压缩不可寻址恢复**——L1 落盘预览不可按 ID 取回；压缩=永久丢失。论文：ARC（可寻址召回 99.4% vs 88.1%）、PRO-LONG/Zero-Mem（保留原文+检索优于生成摘要）。

**缺口 6：压缩触发被动 + 无频率控制**——纯阈值；无 monitor 采样/冷却；1M 窗口下阈值 690k 永不触发（实测）。

**缺口 7：摘要不可修订、不保留约束、无质量闭环**——一次性生成；无逐字保留指令（实测约束被改写）；无"压缩后行为"检查。论文：Governance Decay（约束擦除 38%）、C-DIC（修订优于重写）、SWE-MeM（压缩后重复获取信息 = 质量差信号）。

**缺口 8：无可见性、无恢复路径、驱逐无生命周期语义**——模型不知道预算；截断后无取回（TokenPilot 证明无 recovery 时 80.9→77.1 且成本反升）；L3 用位置/轮数近似驱逐，没有 active/completed/evictable 语义（completed≠可删，残差效用门控）。

### ① 入口闸：分档截断 + 内容去重 + recovery（P1）

**P1.1 分档截断**（TokenPilot 按工具分档 + SWE-Pruner Pro 保守侧）

```
truncatePayload(payload, tool):
  - read 类工具（read_file/grep/glob/list_dir）：永不截断
    （模型需要文件内容原文做编辑，截断会破坏编辑锚点）
  - 长输出工具（run_shell）：上限 40KB → 固定小预览块：
      头 600 字符 + 尾 400 字符（TokenPilot 证据，非 50/50）
      + "[...truncated N chars...]"
      + 智能保留：含 /error|fail|exception|traceback|exit code|✗/i 的行
        及其所在语句块上下文（避免堆栈变量名断在截断处）
      + 短输出（<2,200 字符）不剪（长度感知保守性）
  - 中长工具（search/symbol_search/brief）：上限 20KB
  - 其他：上限 50KB
  maxChars 进 settings 可配
```

**P1.2 内容哈希去重**（TokenPilot repeated_read_dedup）

```
同一文件/同一命令输出重复出现时 → 替换为预览块
  [repeat of #a1b2c3, 18KB, same content as turn 7]
连续相同调用 > 5 次 → 主动介入提示模型换策略
```

**P1.3 recovery 工具（必须，TokenPilot 消融：无则 80.9→77.1 且成本反升）**

```
截断内容按内容哈希存入 artifact registry
新增工具 context.recall <hash|id>：取回全文注入当前轮
被恢复过的路径自动免截断（ingestion gate）
```

**P1.4 token 估算统一 + 校准**（日志 02）：注册表（qwen→o200k、deepseek/openai→cl100k、anthropic→cl100k×1.1）+ usage 回填校准 + 全系统单一估算器 + reserve 5%→12%。

### ② 红线保护：约束/需求变更逐字保留（P0）

**P0.1 摘要 prompt 保留指令**（compression-agent.ts）

```
"用户明确给出的约束/禁止项必须逐字保留在 '## Constraints' 章节，
 不得遗漏、不得改写。
 用户明确表达的需求澄清/变更必须逐字保留在 '## Active Task' 章节。
 保留约束的完整原文块，而非要点。"
```

**P0.2 质量门控三层**（第一组论文：关键词存活 ≠ 蕴含存活，须块匹配）

```
① 规则层：节省 20-80%（对齐 SWE-MeM）+ 范围一致性
   （声明压 A 段就必须只含 A 段内容，不能混入范围外内容）
② 实体层：5 类锚点 verbatim 存活校验（Self-GC 5 类证据丢失）
   文件路径 / 函数名 / 错误行 / 命令 / 约束原文块
   用确定性逐字块精确匹配（非关键词命中——关键词会放过语义翻转）
③ judge 层（离线）：Self-GC no-impact 评估
   （保留前缀+真实后续回合+LLM judge 打 4 维分），建回归集，在线抽检
```

**P0.3 约束完整性校验 + provenance**（Governance Decay 完整 pinning）

```
- 每轮压缩后校验：上下文必须仍蕴含 pinned 约束（完整性校验）
- pinned 区带权威来源标记：只有最新用户消息（或 USER_CONFIRMED 标记）
  能覆盖 pinned 约束；工具输出（README/日志/文档）声称的"新规则"
  不得进入 pinned 区（防 in-context 冒充攻击，0%→17%→10% 证据）
- [Task] 状态提升（Plans Don't Persist）：
  需求变更检测（用户信道）→ 更新每轮重注入的 [Task] 段，
  约束部分逐字来自用户原文，只有任务状态部分可模型生成
```

### ③ 收台机制：L2 压缩升级（P2）

**P2.1 量化 head/tail**（第一组论文量化结论）

```
head：前 3-5 条消息（或 2-4K tokens，取大者），且 ≤10%×L
      = 系统提示 + 首条用户目标 + pinned 区 + 摘要头
tail：随 L 收缩
      L≤16K 用 20% | 16K<L≤64K 用 15% | L>64K 用 10%
      绝对保底：最近 20-40 条消息 或 8-16K tokens（取小者）
      当前工具调用上下文永不压缩
摘要位置：紧贴 head 之后（吃局部首因，Lost in the Middle at Birth
          scale-free 性质）；与尾部间不留长空档
```

**P2.2 内容驱动保护（pinned 区）**

```
扫描全部历史，命中即按原文保留（不进 middle）：
  · 用户约束消息（policy.ts 中英文正则）
  · 需求变更/澄清信号（改为/其实/重点是/补充/不要/必须/do not/never）
  · 模型输出的关键决策（决定/采用/方案/decided/chose）
pinned 消息按原文保留在摘要之前
```

**P2.3 摘要格式：8 章节分化为 Facts / Process 两类**（Telegraph English）

```
Facts 类（Relevant Files / Key Decisions / Errors & Fixes）：
  TE 式实体-算子子句，实体 verbatim、每子句一个事实、| 分隔：
  Errors & Fixes: E108 @raised_by _check_list_display_item
                  | root: hasattr guard @blocks _meta.get_field
Process 类（Progress / Next Steps）：
  散文但遵守"具体到文件/测试/命令"（SWE-MeM future-plan rubric）
压缩 prompt 显式声明目标 token 预算（tokenizer-aware）
注意 F2-struct 教训：结构化本身无价值，实体保留才有
```

**P2.4 章节粒度修订**（C-DIC：替换 > 融合）

```
每次压缩只取回检索命中的 1-2 个相关章节
用"旧段+新对话"整体重压该章节并替换，其余章节不动
未被取回的章节不得被全量重写波及
陈旧检测：某章节超过 N 次压缩未被命中 → 标记候选 prune
```

**P2.5 remaining_work 独立条目**（SWE-MeM）

```
压缩产物 = 摘要 + 独立的 remaining_work 条目追加在轨迹末尾
（不嵌在摘要内部——被后续压缩卷走的风险更低）
```

**P2.6 摘要叠摘要**（降级链第 3 级）：只允许"旧摘要段+新对话"合并重压（SWE-MeM Case C 形态），禁止纯摘要再压；叠压次数 ≤2；叠压门控比首次更严。

**P2.7 压缩后行为闭环检查**（SWE-MeM 独有信号）

```
压缩后继续跑若干步，观测是否重复获取已保留的信息
（重复 view 同一文件、重复跑同一测试）
→ 若发生：摘要丢失引用锚点，回滚到 sidecar 版本 / 标记低质量
```

### ④ 冷库：可寻址归档（P3，ARC 全套移植）

```
1. ID 生成：序号（可见）+ 内容哈希（去重键）
   相同内容观察自动去重（ls/git status 重复调用免费去重）
2. 引用格式：[archived id=17, tool=run_shell, size=82KB, ret=0, turn=7,
   preview=头 200 字]
   元数据：创建步数 + 工具签名 + 返回码（ARC：能过滤/判断陈旧/配对）
3. 归档单元：动作+结果配对（Router-Mem 时间邻域），
   支持 recall(id, ctx=1) 带回前后文
4. context.recall 三件套（ARC 防再膨胀）：
   - 物化总预算 16K 字符
   - 单次上限 8K（超长 → 头尾窗口 / 分块游标 _recall-start/next）
   - LRU：超预算时最久未用物化正文驱逐回引用桩（§id 保持可见）
   - 每步召回 ≤2 次
   - 无效 ID → 自动转关键词检索返回候选列表（不静默失败）
5. Cited 契约：模型实际 recall 过的 id 在任务生命周期内
   不可降级为裸 ID、不可驱逐（地址永久有效）
6. 引用目录有界化（ARC 命题 9：全部引用桩同时可见 ⇒ 无上下文上界）：
   上下文内最多保留 N 条引用桩，超出后旧桩移入可搜索归档目录，
   通过关键词检索导航（衔接 memoryRetriever）
7. 取回注入位置：以工具输出形式注入当前轮（不回填历史位置）
8. 清理策略：会话内永久；跨会话 LRU + 摘要降级（本项目自定义，论文空白）
```

### ⑤ 治理：三动作 + 生命周期驱逐 + dashboard + 硬守卫 + 版本化（P4）

**P4.1 fold/mask/prune 三动作**（Self-GC）

```
fold（可恢复）：大文件体/关键 traceback → 原文入 sidecar + 恢复指针
mask（留骨架）：长测试日志 → 保留首尾骨架，省略中间低信号内容
prune（删除）：过时搜索/失败尝试 → 无恢复保证
降级链修正为（ARC 顺序 + Self-GC 语义）：
  内联（短）→ 引用桩（长观察，fold）→ 裸 ID（引用桩降级）
  → mask（结构骨架）→ prune（仅过时/失败内容）
  L2 摘要只用于"思考痕迹"等不可寻址内容 + 空间极度不足时的兜底
```

**P4.2 生命周期驱逐（L3 升级，TokenPilot）**

```
上下文段状态机：active → completed → evictable
每 B=3 轮批量评估一次（不做逐轮微调，避免 cache 破坏）
completed ≠ 可删：残差效用门控（文件路径仍被最近 tool call 引用 = 保留）
evictable 判定需证据（完成证据 + 无未决问题 + 会话已转向新任务）
```

**P5.1 侧信道触发**（SWE-MeM Workflow-only + Self-GC planner）

```
不训练时主 agent 自触发不可靠（实测 2-4% 触发率）：
```

**P5.2 压缩阈值与预算池修正**


## 四、验证指标与基线

### 四层评估（Oracle §8：只报正确率会把"检索失败但蒙对"和"检索成功但推理失败"混在一起）

### 基线数据（2026-08-04，优化前）
