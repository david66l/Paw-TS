## 约束生命周期（Constraint Lifecycle）✅（2026-08-04，方案扩展）

> 背景：用户要求有期限/会过期/会反转（"10 轮后不想这么做了"、"反着来"）。
> 红线保护防住了"约束被压丢"，但没防住"过期的约束还赖着不走"。

### 设计
- **约束不是永久红线，是带状态的指令**：`ConstraintRecord {text, sourceTurn, status}`，
  状态 active（注入红线区）/ superseded（被覆盖/反转/撤销）/ expired（过期）
- **判定全归 LLM**（用户明确要求：固定词匹配会漏掉真实意图变化）：
  - harness 侧规则**只决定"什么时候该问"**：新用户消息（非最小回复）/ goal 变更 / 15 轮强制 / 任务转向信号
  - LLM 一次辅助调用输出 `{keep:[], add:[{text}], drop:[]}`——默认 keep（忘记=保留，安全方向）
- **降级安全**：LLM 故障/解析失败 → keep 全部 + 规则提取追加，**绝不因故障丢约束**

### 改动
1. **`task-state.ts`**：`constraints: string[]` → `ConstraintRecord[]`（兼容旧格式 resume 升级）；
   `activeConstraints()` / `updateConstraints()` / `updateGoal()`；formatter 只渲染 active
2. **新文件 `agent/src/constraint-reconcile.ts`**：prompt 构建（现有约束 + 新用户消息）+ 宽松 JSON 解析 + 降级
3. **orchestrator `maybeReconcileConstraints`**（每轮执行，子 Agent 跳过）：
   - 扫描用户消息（排除工具结果与系统注入前缀）
   - 触发：新消息候选 + 冷却（调和后 3 轮）/ 15 轮强制（需已有约束且非初始轮）/ goal 变更 / 任务转向
   - 调和后 `task.constraints.updated` 事件（active/superseded/ok）
4. **红线区联动**：`[Constraints]` 段只注入 active 约束（附来源轮次），内容变化才 upsert
5. **压缩门控联动（关键）**：摘要逐字校验只对 **active** 约束生效——
   被反转/撤销的旧约束不再卡死压缩（原来从 middle 提取，现在从 taskState 取）

### 场景覆盖
| 场景 | 机制 |
|------|------|
| 用户中途"改用 Y"（反转"不要用 X"） | LLM drop 旧约束 + add 新约束 → 红线区只留新的 |
| 用户说"算了/别管了"（撤销） | LLM drop → 红线区清空 |
| 期限约束（"这周用 A"） | 15 轮强制调和 → LLM 判 expired |
| 新任务转向（"接下来做 X"） | TASK_PIVOT 信号触发调和 |
| LLM 不可用 | 降级：全部保留（不丢红线） |

### 验收
| 验收项 | 结果 |
|--------|------|
| prompt/解析/越界/降级 | ✅ 6 项单测 |
| TaskState 状态流转（反转/撤销/keep/旧格式兼容） | ✅ 4 项单测 |
| e2e 反转：resume + goal 变更 → 调和 → 红线区更新 | ✅ 集成测试（旧约束消失、新约束进入 [Constraints]） |
| e2e 降级：LLM 故障 → 约束保留 | ✅ 集成测试 |
| 回归 | ✅ core 233、agent 186（1 项 worktree 慢测 30s 超时，120s 通过） |

### 过程中修复的 2 个 bug
1. **15 轮强制在初始轮误触发**：`_lastReconcileTurn=-100` 导致 turn 0 就调和，
   消费了 mock 模型的主回复 → 强制条件加"已有约束 + turn>0"
2. **系统注入消息混入候选**：`[Context Package]` 等被降级规则提取为约束 →
   候选过滤排除系统注入前缀

### e2e 实测发现的 5 个真 bug（已修复）
1. **tail 绝对保底固定 8K/20 条**在 32k 小窗口下吃掉 middle → 压缩永不 savings 达标。

3. **系统锚点（[Context Package]/[Previous session context]）计入 head 预算**：30K 字符锚点撑爆 head → 边界错乱。
   修：`isContextAnchorMessage`——锚点不计预算、总是保留在 head（C AT Q 区语义）
4. **auto-context 注入上限过大**：`discoverContext` 8 文件 × 8K 字符 = 64K 字符 ≈ 16K tokens 一次性注入。

5. **o200k_base 首次加载 ~20s**：`TiktokenEstimator` 构造即加载 → 首次 run/测试卡 20s。
   修：懒加载（首次 count 才加载）+ `prewarmEncoding` 后台预热（orchestrator 对 qwen 系模型自动预热）
