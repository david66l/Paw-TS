# 03 工具调用解析失败不反馈（P0-1）

- 状态：已修复
- 日期：2026-08-04

## 问题

**现象**：模型输出无法解析时，系统不反馈、不重试，静默吞掉——模型永远学不会修正格式。

**根因**（一个根因，两个表现）：
1. **文本通道**：模型写了坏 JSON（引号错、字段缺、被截断）→ 解析返回 null → `handleNoAction`（`orchestrator/action-handlers.ts:159`）把它当纯文本回复，或推一条与格式无关的"你没给 final_answer"提示；更糟的是没用过工具时直接**降级为 completed**，任务没做就说做完了
2. **原生通道**：tool_use 的 `arguments` JSON.parse 失败 → **静默用 `{}` 空参数执行工具**（`orchestrator.ts:1747-1756` 修复前），参数丢了还执行，比解析失败更危险

**伴生小洞**：未知工具名静默丢弃（`orchestrator.ts:913` filter）；`toolCallDedupKey` 用 `JSON.stringify(args)` 键序敏感，去重失效。

## 调研

### 参考实现：OpenHands（software-agent-sdk，2026 版）

实际阅读源码确认，关键文件：
- `openhands-sdk/openhands/sdk/agent/response_dispatch.py`：`classify_response` 四态分类（TOOL_CALLS/CONTENT/REASONING_ONLY/EMPTY）；`_handle_no_content_response` → `_send_corrective_nudge`：注入 **role="user"** 消息（source="environment"），循环继续，不降级完成
- `openhands-sdk/openhands/sdk/agent/agent.py`：`_get_action_event` 参数校验失败 → `_emit_tool_error`：**拒绝执行**，arguments 替换为 `{"_openhands_malformed_tool_call": True, "error": ...}` 注入事件，错误信息只含参数名不含值；未知工具名反馈 "Tool not found. Available: [...]"
- `openhands-sdk/openhands/sdk/agent/utils.py`：`fix_malformed_tool_arguments` 按 schema 修复 GLM 式畸形（JSON 字符串编码的数组/对象、被 chunk 的字符串）
- 顶层兜底：`FunctionCallValidationError` → 注入 user 错误消息 → 循环继续

### 结论对照

| 方案 | OpenHands 实际 | 验证结果 |
|------|---------------|---------|
| 格式反馈用 user 消息注入 | role="user" + source="environment" | ✅ 一致 |
| 坏参数拒绝执行 + 错误注入 | `_emit_tool_error` | ✅ 一致，并学到细节：错误只含参数名不含值 |
| 未知工具名静默丢弃 | 有反馈（含可用列表） | ❌ 修正为反馈 |
| 主动修复畸形参数 | `fix_malformed_tool_arguments` | ✅ 新增该层 |

## 解决方案（已实施）

1. **解析诊断层**（`parse-agent-action.ts`）：新增 `diagnoseParseFailure()` 三态诊断——`ok`（纯对话）/ `malformed`（JSON 语法错误/截断，带行号）/ `invalid`（字段缺失/未知工具名，带可用工具列表），纯规则零 LLM 调用
2. **格式反馈回路**（`action-handlers.ts`）：`handleNoAction` 新增分支——输出有工具痕迹但解析失败 → 注入 user 消息（具体原因 + 正确格式示例）→ continue，**不再静默降级为 completed**；`formatErrorNudges` 独立计数（上限 2，与 auto-nudge 互不干扰）
3. **原生通道坏 args 拒绝执行**（`orchestrator.ts`）：流式分支坏 JSON 收集进 `nativeToolErrors`（原始输入），不 push 执行列表；新 `handleNativeToolErrors` 把错误以工具结果注入（模型直接看到自己发的内容和错误）；未知工具名改为 "Tool not found + 可用列表" 回灌
4. **字段级修复层**（新文件 `orchestrator/fix-malformed-args.ts`）：按工具 schema 解码 JSON 字符串编码的数组/对象、拼回被 chunk 的字符串、递归处理嵌套，双通道执行前应用
5. **`toolCallDedupKey` 键序无关**：稳定序列化（对象键排序）
