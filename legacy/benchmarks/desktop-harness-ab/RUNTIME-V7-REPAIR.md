# 验证与收尾修复（2026-09-07）

本轮将上次 DeepSeek 隔离测试暴露的三个问题落实到最新桌面运行时：不可信验证结果的识别与直接重跑指导、临近预算时的收尾提示、最后一个模型轮次的工具执行边界。没有更改模型 max、原生输出容量或扩大模型轮次预算。

## 实现与旧运行时对照

- **共享命令判断。** 将旧 `packages/agent/src/shell-command.ts` 的纯解析实现迁到 `packages/core/src/shell-command.ts`，并迁入旧 `verification-command.ts` 的 `exitStatusProvesVerification()`。旧路径保留转导出，旧运行时继续使用同一实现。新 `packages/completion-review/src/evidence-projector.ts` 也复用它，覆盖管道、OR 回退、顺序/后台命令，保留有效 `&&` 链和带引号的普通参数。退出码被掩盖时既不算通过，也不当作明确的断言失败。
- **明确纠正之前的判断。** v6 的 `masksVerificationExitV1()` 实际只识别验证命令后的分号，不包含管道。此前报告把它描述得过于完整。真实测试中的 `| tail` 漏判在本轮才修复；不能把旧退出 0 视为可信测试通过。
- **直接验证指导。** `packages/progress-advisor/src/projector.ts` 新增 `verification_repair`，沿用旧 `convergenceGuidance()` 的意图：先查看实际错误或超时，再直接运行同族测试，避免通过反复换输出过滤器诊断。按修改版本、最近直接验证基线及验证类型去重，每工作段最多两条，旧消息保持原有历史位置。它是建议，不自动执行命令或绕过审批。
- **收尾提示。** 新增 `convergence_checkpoint`，使用旧 `convergenceWindow()` 同样的窗口公式，基于冻结的段内/全局剩余轮次，在进入窗口及剩余两轮时最多提示两次。结合修改后的检查结果，要求修复确切失败、执行项目声明的测试入口、检查文档和剩余要求、保留最终答复。小于 8 轮的短任务不追加这类提示。迟到后台检查不冒充最新修改已验证。
- **末轮工具边界。** `packages/agent-loop/src/interactive-control.ts` 新增冻结配置 `settleFinalToolBatch: true`。桌面新 profile 启用；达到模型轮次上限后仍允许已观察到的本轮工具完成，结算后停止，不再发起下一次模型请求。未启用的历史配置保持原语义；取消、权限拒绝、未知副作用和跨段总预算仍有效。不把末轮工具成功自动标记成完整任务交付。
- **证据可以被后续检查更新。** 同一个测试被管道过滤后的记录和直接重跑记录归到相同验证目标，后续直接通过可取代之前不确定的结果，防止过时记录反复要求审查。
