# 桌面长任务 Harness 真实模型初测

日期：2026-09-06。协议：v3；完整原始记录在 `.runs/2026-09-06T11-31-41-936Z/`。

本轮用实际桌面宿主 `runDesktopNext`，对比当前代码的普通流程与长任务流程。模型均为 GLM-5.3-Flash，思考强度 max；每组 12 分钟、40 次模型调用、160k 已报告 token 停止阈值。模型回复与原生恢复配置保持不变。所有调用共用预算，阈值可能被一笔在途请求超出，缺少 usage 的调用不能按零成本处理。

这是每条件一次的排错初测，尚未体现长任务模式收益。它不是历史旧运行时对比，也不能给出统计显著的成功率结论。

## 中断恢复

预设在业务文件首次写出后的成功工具结算点强制终止进程，等待 95 秒租约过期，再恢复同一会话。两次尝试共用原预算。

长任务组在预算内未写出业务文件，因此没有触发中断；不能据此判定恢复成功或失败。普通组确实触发中断，随后沿用同一运行 ID 继续写出存储模块、CLI、文档和测试；总耗时 565 秒（含租约等待），外部抽查 15/15。它触及 token 阈值后中止，并未完整完成运行时验收。

普通恢复组自带测试命令 `node --test test/` 在本机 Node v24.15.0 下报 MODULE_NOT_FOUND；直接指定 `test/queue.test.js` 补测为 15/18，失败包含断言不一致和未定义变量。因此能确认同一会话恢复执行并继续产出，不能宣称完整交付成功，更不能据此证明长任务 Harness 的恢复优势。普通流程两次队列运行结果不同也提示样本波动明显；不能把这次产出提升归因于人为中断。

## 已确认的问题

1. **嵌套只读审计启动失败。** 离线确定性复现捕获到 `Duplicate or empty permission rule id: deny-child-write`。父只读任务的硬性禁止规则被继承后又追加同名规则，审计员尚未调用模型就被权限引擎拒绝；外层只显示 `AuditUnavailable`。不能把这个状态当作模型验收能力不足。
2. **任务派发反复无效。** 多次出现 acceptance 字段长度错误，以及目标、范围、验收条件组装后超过 4000 字符的限制；错误反馈没有精确定位，模型重复提交仍无法执行。
3. **前置检查挤占执行预算。** Manager 多次要求重复读取、目录清点和环境确认；有些要求超出只读角色能力。
4. **模型回复预算需要单独调优。** 桌面规划器通常显式请求 8192 输出额度；GLM 的 max 思考与截断恢复相互影响，队列样本消耗较多时间却没有落盘。不能仅把通用恢复默认值改大就假定解决。

本轮修正了 Windows 大小写等价工作区根目录被误判越界的问题，两组共享该修正；路径安全回归和 workspace 类型检查通过。其余运行时行为在正式 v3 对照中保持冻结。

最终检查：路径安全与评测器校准合计 13 项测试通过，workspace TypeScript 检查通过，评测运行器和报告生成器构建通过。评测器现将无输出、超时和不完整结果标为未测得，并避免聚合时覆盖独立复核结果；这些修正不改变已冻结的模型运行产物或原始用量。
