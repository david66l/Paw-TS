# V34：交付状态与请求预算准入

这次改动接入标准桌面新运行时，针对 [V33 复测](RUNTIME-V33-WORKFLOW-RETEST.md) 暴露的交付遗漏、错误测试断言和截止前仍发请求问题。本文记录初次离线与生产桌面宿主集成验证；后续真实 GLM 结果及枚举类型校验修复见 [V34 复杂任务复测](RUNTIME-V34-WORKFLOW-RETEST.md)。

## 交付项与证据关联

复用旧运行时的 `workspace.acceptance_update` 工具及 Harness 执行适配，采用其来源、状态、证据和改动后重新验证的做法。旧实现位于 `packages/agent/src/task-state.ts`、`packages/agent/src/lifecycle/acceptance-gate.ts`，新接入位于 `apps/cli/src/paw-next/delivery-ledger.ts`。

- 新标准桌面会话通过 `deliveryLedger: true` 启用工具，注册表哈希参与运行身份；没有该字段的旧会话保留原目录和恢复身份。旧长任务 manager 和子 agent 的工具范围本次不扩展。
- 模型可登记具体交付项及其来源，包括明确要求的入口、配置、文档、行为检查。保留 pending、satisfied、blocked、superseded 状态，最多 32 项，每批只允许一次清单更新。
- `satisfied` 的 evidence 必须引用精确的实际工具 callId。成功写文件或一段“已完成”的描述不足以满足校验；可以引用成功读取文件，或保留真实退出码的直接命令、测试等检查。
- 验证与模型声明分开：`evidence_linked` 仅表示已关联当前可采信的观察，不证明该检查覆盖整条需求，更不是独立验收通过。文件读取也仅能证明其实际读取范围。
- 后续修改、可能产生部分影响的失败修改、并行重叠修改、后台任务启动后的修改都会使有关旧证明失效。同一目标较新的失败会取代旧通过；目录不同的同名测试不会互相覆盖。
- 新用户工作项使用自己的记录；steering 保留当前工作项。工具成功结算是日志提交点，恢复从同一日志与校验过的归档载荷重建，不再维护第二份可漂移数据库。
- 新执行器原先没有转发 `acceptanceLedger` 服务，桌面真实集成测试发现并补齐了这条迁移连接。

上下文投影最多 6,000 字符，优先保留未解决项并显示省略数量；不解析文件系统或额外调用模型。未使用清单工具的任务没有清单上下文。工具 schema 和使用清单本身仍有开销，本次不宣称零 token 成本。

## 临近截止的新请求判断

显式限定总时间的新桌面工作项启用 `recent_round_floor_v1`。它在下一轮安全边界、构建上下文之前，使用日志中最近最多五个已完成模型与工具回合的最短耗时作为经验下限；剩余时间小于该值时，不再发起下一次模型请求。

这避免按 GLM 某一题硬编码固定秒数。没有历史样本时不拒绝首次调用；没有显式总时限的普通任务也不加默认限制。准入策略与原绝对截止时间一起记入预算事实，恢复不能移除策略或重置预算，时钟观察不能倒退。

停止沿既有非重试运行失败记录保留原因，桌面将这一受控情况展示为“剩余时间不足，任务未完成”，不会宣称成功或自动重试。已有产物保留。原在途取消机制仍生效。

这个最短耗时是经验启发式，包含工具执行开销，不是对下一次模型请求的准确预测：后续更短的请求可能本来能完成，更长的请求也仍可能超时。下限和最后五轮窗口的实际收益，需要后续对照实验；它不能在长思考中途注入新提示。

## 尚未解决

模型仍负责识别并登记要求；未登记项不会自动变成清单。现有独立完成审查继续负责实际接受判断，清单本身不决定完成，也不保证测试断言正确。长思考的根因、本轮完整交付率以及新增工具与状态的净 token 开销，需要新的真实任务实验确认。

下一次复测应冻结本版源码，沿用相同模型、权限和验收规则，同时检查登记覆盖是否完整、首次真实入口检查时间、README 等交付物、自带测试质量及准入拒绝前的剩余时间。不能只看一次 token 数或首个工具时间。
