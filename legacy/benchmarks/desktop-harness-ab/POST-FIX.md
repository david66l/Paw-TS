# 长任务 Harness 修复与离线验证

日期：2026-09-06。本次修复在六组协议 v3 真实模型运行结束后进行，没有修改那一轮任务产物、用量或评分；历史结论仍见 [RESULTS.md](RESULTS.md)。

## 修复内容

- 嵌套只读审计：保留继承的 hard/admin 禁止规则。只有层级、目标和动作完全相同的 deny 规则才复用；同名但不同目标的规则均保留，给新规则分配稳定且不冲突的 ID。无效父策略继续由权限引擎拒绝。普通父任务的默认授权不会扩散到子任务。
- 派发长度反馈：错误指出任务 ID、字段下标、实际长度和上限。合并上下文超过限制时，分别报告 goal/scope/acceptance/格式占用及至少需要减少的字符数。原有 4000 字符限制保持不变，不截断验收条件。
- 工具说明：显式告知模型总长度包含标题和列表格式，建议引用工作区文件，避免复制全文。

## 验证结果

- 新增的真实组合路径测试先在旧实现下失败；修复后，只读阶段能启动嵌套审计员，审计员实际读取证据文件，返回 verified。
- 权限合并覆盖多级继承、不同 ID 的相同规则、同名不同目标、父策略不被修改，以及歧义父规则仍被拒绝。
- 派发边界通过实际工具注册表验证：恰好 100 字符可接受，101 字符返回占用明细；另覆盖过长、空、非字符串验收项及超出数量限制。
- 协作、环境审计、权限及运行时组合测试：110/110 通过。桌面宿主、状态投影和自动任务安排测试：25/25 通过。
- CLI 与 collaboration 的 TypeScript 检查通过；新增权限模块及协作改动的 Biome 检查通过。

使用 `diagnose-readonly.ts` 再次运行两个确定性模型场景（短报告/长报告）：修复前均因重复权限规则导致零次审计员调用、unverified；修复后均为 4 次审计员调用、错误列表为空、completed/verified。记录：[修复后桌面复现](.runs/post-fix-audit-2026-09-06.json)。这些回复是脚本预设的，只验证执行与审计通路，不代表模型完成真实任务的能力提升。

本修复阶段没有调用付费模型，仅进行了离线验证。后续真实复测采用相同任务、模型和预算。Manager 的重复前置检查与 GLM 思考/回复预算保持不变，避免同时改动导致结果无法归因。
