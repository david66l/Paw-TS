## 实现

### 由宿主提供真实时间预算

- `DesktopNextOptions.executionDeadline` 接受绝对截止时间 `deadlineAtMs` 和收尾预留 `reserveMs`；普通桌面任务未提供该选项时，不设默认总时限。
- 桌面端把到期信号与原取消信号合并，沿已有执行链路传递到模型和工具。迟到的模型结果不能在取消后发起工具执行。
- V3 在模型请求安全边界记录 `execution.budget_observed`，与当前用户工作项绑定。提示读取日志中的时间观察，不在上下文投影或 reducer 中读实时钟。
- 在预留时间以内，即使模型调用余额充足，也提示优先直接验证用户入口、修复具体失败和补齐要求的交付物。此提示不会改变权限或降低验收标准。
- 恢复沿用原截止时间；更换截止时间或预留值会被拒绝。日志观察时间不能倒退；新的用户工作项可以有独立预算，steering 不会重置当前工作项。
- 基准脚本把既有外层预算传给桌面端：预留为 `min(180 秒, 总时限的 20%)`。恢复运行不再提交一个重新计算的截止时间。

参数示例：

```ts
executionDeadline: {
  deadlineAtMs: Date.now() + 20 * 60_000,
  reserveMs: 3 * 60_000,
}
```

这是嵌入宿主接口，不新增桌面按钮。直接使用 V3 嵌入接口的其他宿主仍需自行提供覆盖在途操作的取消信号；边界观察本身只在请求之间检查是否耗尽。

### 渐进式验证

新桌面运行记录通过 `incrementalVerification: true` 选择新指引，参与既有配置身份计算；没有该字段的旧记录保留原提示词和恢复身份。

指引要求复杂任务先连通入口、核心行为、必要读写和一项直接验证，再扩展范围；明确要求的配置、文档也属于交付。后续修改影响已测路径时，相关验证需要更新。小任务使用相称检查，不强制新建测试框架或阶段流程。

已有实现继续承担验证新鲜度与调用次数收尾判断：`packages/progress-advisor/src/projector.ts`。旧运行时 `packages/agent/src/lifecycle/convergence.ts` 中的真实退出码、当前改动与收尾原则也保留在这次指引中，没有再造一个规划循环。

## 验证

最终相关回归为 **148 项通过、0 项失败**（11 个测试文件，15.79 秒）；CLI 共享运行时及桌面前端/宿主 TypeScript 检查通过。

覆盖范围包括：

- 48 次模型调用尚未耗尽，但实际时间已进入收尾预留；上下文仍提示收尾。
- 相同日志快照重复投影一致；无显式预算时不制造时间限制或额外模型调用。
- 严格日志拒绝预算重置、未提升输入、倒退或非法时间。
- 真实桌面宿主到期取消不响应取消的模拟模型，拒绝迟到工具调用和超时后的恢复延期。
- 完成任务恢复不重放模型；同一对话的新工作项不继承旧预算。
- 旧会话身份、验证新鲜度、工作状态、V3 产品身份与原生工具上下文回归。

测试结果和类型检查记录保存在被 Git 忽略的 `.runs/execution-budget-*.log`。这些测试使用可控模型与临时工作区，不调用真实 GLM，也不启动 Docker 或常驻服务。

## 尚未证明或实现的部分

- 最小用户路径目前是执行指引，尚不是自动生成并强制执行的端到端验收器。
- 尚无逐项结构化的“需求—产物—验证”覆盖账本；此次不能保证模型绝不遗漏交付项。
- 现有调用次数限制与新增时间提示并存，尚未形成统一的货币或 token 成本预算调度器。
- 剩余时间只能在请求边界更新给模型，不能把新提示注入正在进行的长思考；到期取消沿现有链路处理。
- 未新增自动重试、独立规划模型或多 agent，因此没有新增这类模型调用开销；提示文字与预算日志本身仍有小额开销，未作性能收益测量。

下一次性能验收应冻结这版源码和任务，在同一模型、effort、工具权限、总时限下做配对重复实验。主要看独立验收的首次完整交付率、成功交付耗时、包含失败尝试的总用量与错误宣称完成次数；首次写文件时间仅作为诊断指标。单次相同题目改善不足以证明整体领先。
