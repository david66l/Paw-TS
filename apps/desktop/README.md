# @paw/desktop

Paw 桌面端：**Electron + React + TypeScript + Paw Next V3**。

- 三栏布局：侧栏 / 对话 / 右侧 Plan·任务·后台·Changes·Context·Memory
- 浅色液态玻璃（对齐 `prototypes/ui5-1to1`）：`GlassPanel`（CSS 仿真，非 SwiftUI 系统材质）
- **执行引擎已切换到 Paw Next V3**：Electron 启动 Bun 宿主，通过行协议接收流式回复和已提交的运行事件
- 支持流式回复、工具调用芯片、Markdown（`react-markdown` + `remark-gfm` + `remark-breaks`）、快捷示例与新对话

## 外观皮肤

打开左下角 **设置 → 外观 → 皮肤**，可选择「静谧」「极光」或新增的 **「纸间 · Louis」**。

「纸间 · Louis」沿用 Louis.dev 博客的暖纸底色（`#f0eee6`）、薰衣草紫（`#8061a5`）、细描边和衬线标题，搭配纸纤维纹理与植物插画。侧栏、聊天、Markdown、输入框和右侧面板使用同一套配色。界面字体为 Inter，标题为 Newsreader，中文使用系统字体回退；字体与图片随应用打包，无需联网加载。

皮肤选择自动保存在本机。纸间皮肤使用哑光纸面；切回静谧或极光时，会恢复之前选择的「柔雾 / 折光」材质。

资源位于 `src/assets/paper/`，字体许可证随资源保留；配色与主题状态分别位于 `src/styles/paper.css` 和 `src/styles/appearance.ts`。

## 开发

在仓库根目录：

```bash
bun install
# 若 electron 报 failed to install correctly，补下二进制：
cd apps/desktop && bun run rebuild-electron && cd ../..
bun run desktop
```

或：

```bash
cd apps/desktop && bun run dev
```

会启动 Vite（5173）并打开 Electron 窗口。

校验前端与宿主类型、运行测试并打包（不启窗口）：

```bash
cd apps/desktop && bun run typecheck && bun run test && bun run build
```

## 架构

```text
React UI → Electron IPC → Bun agent-host
                          └─ @paw/cli/paw-next（共享 V3 组装入口）
                             ├─ 持久化 Session / 工作段 / 执行租约
                             ├─ Agent Loop / 工具审批 / 检查点
                             ├─ Collaboration 调度 / 独立子 Agent
                             └─ Memory Plugin → PostgreSQL
```

桌面不再调用 `runStubRun`、旧 `AgentOrchestrator` 或 `AgentGroup`。CLI 与桌面共享同一套 Paw Next V3 实现；`@paw/agent` 仅用于已有的 Agent 配置、沙箱配置和诊断工具。

- **多轮对话**：正常结束后，下一条消息开启同一个持久化 Run 的新工作段，保留模型上下文。清空聊天时明确切换持久化运行身份，重启桌面后仍生效；空历史数组本身不会重置 Run。更换模型、审批配置、技能或花名册时，新 Run 接收已有聊天历史。旧聊天记录与「纸间 · Louis」皮肤继续可用。
- **多 Agent**：工具委派由 Paw Next Collaboration 执行。桌面卡片根据已提交的任务、工具与结算事件更新，调用 ID 带 Run 命名空间。子 Agent 流式文本与主回复隔离。原 AgentSpec 的 `flash/pro/inherit` 模型偏好映射到独立子模型，绑定参与配置校验；`inherit` 沿用当前根模型。`orchestrated/team/multi` 模式读取原根 Agent 的提示和模型偏好，执行仍由 Paw Next 负责。
- **运行中追加指令**：输入框保持可编辑，点击「追加指令」将要求写入当前 Run 的持久化 Inbox。气泡分别显示「已接收」和「已纳入上下文」；后者表示在当前模型调用或工具批次结束后完成投递，不代表任务已完成。回执失败时保留草稿，重试复用输入 ID。模型准备自然结束时，已接收但未处理的追加指令会继续执行，仍受回合预算约束；任务已结束或正在停止时明确拒绝新的投递。
- **子任务控制**：活动卡可单独停止正在执行的子 Agent，其他子任务继续，主任务收到取消结果后收尾。子任务的待决审批随取消关闭，已经完成的文件修改不会自动回滚。失败或已停止的子任务可点「重新委派」，向主 Agent 提交包含原任务目标、范围和验收要求的新指令，先检查已有改动，再创建新委派；这不是对旧调用 ID 的直接重放。主任务已中断时，需先恢复主任务。卡片提供各子任务的结果摘要。
- **附件**：输入框可选择 UTF-8 文本、代码以及 PNG/JPEG/WebP/GIF 图片，支持仅附件发起任务、后续续聊和运行中追加。每次最多 4 个文件，文本每个 256 KiB、图片每个 2 MiB，编码后的总内容不超过 6 MiB；不支持 PDF、Office 文档和其他二进制文件。图片理解取决于所选模型是否支持视觉。附件通过 V3 文件产物持久化，跨工作段进入模型上下文；聊天历史保留文件名，重试使用相同输入身份去重。
- **任务总览**：右侧「任务」展示委派任务的依赖、状态、范围和验收要求；失败或取消的前置任务会显示后续阻塞项。子任务结算后汇总结果、修改文件、产物引用和测试结果；这些内容来自运行事件和子任务实际返回的证据，不代表桌面额外执行了测试。
- **后台任务**：Agent 启动的后台 Shell 任务显示在右侧「后台」，包括主/子 Run 的状态、最近输出和单任务停止按钮。界面轮询使用独立的日志预览，不消费 Agent 的输出游标；保留受任务输出上限约束的日志尾部，界面最多展示约 64 KiB 字符。任务结束后的快照可重新查看。监控快照覆盖保存，轮询日志不会不断追加到聊天历史。
- **审批与停止**：默认读取允许，修改与 Shell 操作询问；「自动」模式沿用设置。「本会话始终允许」只复用同类参数授权，子 Agent 同样受审批约束。停止时取消运行及待决审批。
- **检查点**：`/checkpoints`、`/undo` 解析到 Paw Next 的 Session/Run 检查点命名空间；历史 Run 的检查点仍可读取。
- **长期记忆**：使用 Paw Next Memory Plugin 的 PostgreSQL 作用域检索与工作段结束写入。新 Run 的任务成果须先通过独立环境验收，用户明确要求记住的偏好仍可单独写入。沿用 `DATABASE_URL`、`tenant_id`、`user_id`、`repository_id`、`workspace_id` 的作用域规则；`paid_memory_extraction: false` 切为只读。右侧记忆库读取相同的长期记忆表。数据库不可用时显示降级结果，聊天仍可运行。
- **设置与技能**：沿用 `.paw/settings.local.json` 中的模型预设、`max_steps`、沙箱和 `mcp_servers`；桌面不再强制覆盖为 24 步。工作区 `.paw/skills` 列入技能目录，由 Agent 按需读取。MCP 工具经发现后绑定到 V3 允许列表。
- **界面投影**：Plan 接收成功提交的 `todo_write`；Changes 从已提交、经哈希与调用绑定校验的产物中读取主/子任务文件差异；Context 展示新运行时的输入预算、固定上下文、输出预留和裁减估算，并保留实际模型用量与费用。需要补充信息时，Agent 在聊天中提问，用户下一条消息继续工作段。`await_user`、`await_external`、`incomplete` 分别显示等待回复、等待外部任务和尚未完成；旧 ask_user 卡片协议只保留兼容，不作为新运行时的提问入口。

执行日志位于 `.paw/paw-next/sessions/`；`.paw/desktop-next/` 保存桌面对话到 Run 的索引与 `<runId>.monitor.json` 任务/后台面板快照（包括输出和结果摘要）；`.paw/sessions/` 保留供 `/sessions`、`/replay` 读取的界面事件投影。模型凭据仍由设置加载，不写入桌面索引。

异常退出后可点击「恢复任务」，由 V3 读取权威日志、分类并恢复同一个 Run。后续工作段的输入 ID 在提交前持久化，恢复时复用该 ID；已完成的工作段不会重新调用模型。配置变化时拒绝恢复，需恢复原配置或新建对话。存在未知工具结果时，由运行时的恢复规则决定是否可以继续，不把中断任务自动重发为新任务。桌面运行配置显式绑定追加指令策略；没有该策略的历史 Run 恢复时沿用原语义，不开放运行中追加输入，正常下一轮会使用新配置。桌面重启后，未结算的面板记录会标记为中断；后台任务不会仅凭旧 PID 自动重连或恢复。监控快照用于展示，恢复执行仍以运行时权威日志为准。

## 独立环境验收

新的桌面 Run 默认启用 `paw.environment-audit.v1`。文件修改或已有完成度检查触发验收时，Paw Next 启动独立的审计子 Run：使用新的上下文读取实际文件，再对照原始目标、当前用户任务和追加要求判断是否满足验收条件。执行者的回复和测试摘要只作为检查线索。

右侧「任务」提供 **本阶段验收**，分别显示「待核验」「尚未通过」「修复中」「已验证完成」，以及实际检查的文件和未满足的要求。子任务的「执行结束」仅表示执行结算。主运行已结束但验收未通过时，桌面返回 `incomplete`，不展示为验收成功。

审计员仅允许 `read_file`、`list_dir`、`glob`、`grep`；禁止修改、Shell、MCP 和再次委派。宿主将成功读取的文件与工具结算绑定，保存内容哈希、验收结论和审计子 Run 引用。只有实际读取的证据、稳定的文件内容和通过结论同时具备，才会标记验证完成；缺少证据、报告格式错误、超时或审计期间文件变化均不能通过。

每次审计最多 12 个模型回合、120 秒；每个 Run 最多自动追加 2 次修复工作段，且仍受主运行剩余预算限制。预算不足时保留尚未通过状态。审计会产生额外模型调用；纯聊天无需文件验收。恢复时沿用持久化策略，已结算且文件未变化的审计可以复用，文件变化后重新核验；没有该策略的历史 Run 不会在恢复时偷偷切换策略。

当前范围是**文件证据审计**：审计员尚不能直接操作浏览器或桌面、检查截图、运行测试命令，也不等同于完整的端到端行为验证；缺少必要的行为证据时应报告待验证项。历史面板展示的是上次保存的结论，当前文件有效性在运行恢复时核对。长任务模式已接入 Manager 与分轮独立执行；长期记忆的成果来源限制见下一节。

## 经过验收的记忆来源

新桌面 Run 在启用环境验收时默认绑定 `paw.audited-memory.v1`。写入发生在独立验收之后、下一工作段开始之前；验收未通过时不提取任务成功经验。该策略进入持久化配置哈希，历史 Run 恢复仍沿用原策略，正常开启新配置的任务才启用新限制。

长期记忆只接收两类来源：**用户原话**与**宿主验证通过的独立验收报告**。报告保留 review ID、候选哈希、审计子 Run、文件路径和内容哈希；成果原子的来源序号必须引用有效验收报告。用户明确要求记住的偏好或规则可按用户陈述写入，即使当前文件任务失败，也不会丢掉这类要求。系统自动生成的修复反馈不属于用户原话；切换配置时导入的历史聊天只作为任务上下文，记忆提取与归档仅保留其中的当前用户请求。

这一限制同时覆盖语义提取和原始证据归档，执行者自述、工具输出、失败报告不会经原始归档绕回长期检索；完整轨迹仍保存在运行日志。写入前以及恢复已暂存的写入时重新核对来源和被检查文件，证据已变化或不可读取则拒绝写入。恢复已结算的记忆不重复调用提取模型或数据库写入。

这是新写入的来源准入规则：不会自动清洗历史数据库，也不会持续撤销入库后因工作区变化而过时的历史记录。验收本身仍受文件证据范围限制；模型提取也不等于对每条陈述做形式化证明。纯聊天不为记忆强制触发文件审计，普通聊天的助手输出不进入新的长期归档。

## 长任务模式

在输入框旁选择 **长任务** 后发送任务。模式选择保存在本机；普通任务沿用原流程。切换模式会使用新的 Run 配置，恢复任务则始终沿用该 Run 保存的模式，不受当前下拉框选择影响。

长任务采用 **Manager → 独立执行阶段 → 独立验收 → 下一阶段**：Manager 只拥有委派、计划与记忆读取工具，不能直接修改文件或运行 Shell。每个阶段必须有明确的目标、scope 和非空 acceptance；scope 描述任务范围，实际文件权限仍由 AgentSpec 和原审批规则决定。执行者使用独立子 Run，只接收当前合同和必要的依赖结果，不自动继承前一个执行者的完整轨迹。修复通过新的委派和新的执行上下文完成。

阶段执行结束后，先进行独立文件验收，再向 Manager 返回成功或未通过。一个委派计划中的阶段依次执行；依赖启动前会核对被检查文件的哈希，未通过或已过期的依赖会阻止后续阶段。任务面板展示各阶段的验收状态和证据文件。最近的阶段计划失败时，不能直接宣布整体完成；重新委派成功后，仍需对照用户完整任务做最终验收。

每个用户任务最多启动 **12 个执行阶段**，包含失败和修复尝试；恢复同一委派不会再次占用名额，系统修复反馈不会重置计数。执行者受已有单阶段回合上限和委派计划总预算约束，审计另受 12 回合 / 120 秒上限约束，Manager 也受主运行预算限制。以上是调用次数和回合边界，不是固定费用保证；长任务会增加模型成本。

运行中追加要求时，当前阶段可以收尾，尚未开始的旧计划阶段会暂停，由 Manager 纳入新要求后重新安排。恢复期间，只有已经持久化授权的长任务委派能依据原调用 ID 和子 Run 日志继续；普通工具或子 Run 中未知的副作用仍按原恢复规则停止。阶段间进程退出的测试确认：恢复后继续剩余阶段，不重复已完成的文件写入。

当前长任务面向文件与代码工作。Manager 和执行阶段不开放 MCP；普通模式仍保留原 MCP 支持。验收的 GUI、浏览器操作和测试执行能力仍受上一节限制。跨计划的显式依赖追踪见下节。长期记忆的自动成果写入绑定最终验收报告，执行子任务不直接写入长期记忆。

## 跨计划成果依赖

新建的长任务默认绑定 `paw.stage-graph.v1`。每个阶段的独立验收、文件哈希和子 Run 引用写入父运行的持久化活动结算；阶段合同、依赖和替换关系来自已派发的委派调用。恢复时从权威日志重建，桌面缓存不决定执行结果。历史长任务恢复沿用其原来的工具与配置身份。

Manager 可以在后续计划中声明对已有阶段的依赖，也可以用新的阶段替换旧阶段。新的替换必须保留原阶段的范围和验收条件，并引用原依赖的当前版本；不能通过省略依赖、引用已被替换的旧版本，或依赖被替换阶段的下游来绕过重验。

每个阶段启动前、计划返回时和最终验收前都会检查文件版本。上游证据变化或上游被替换，会使已有下游及其间接依赖失效。**上游修好不会自动把旧下游恢复成有效**：Manager 需要以新的独立阶段重验或修复下游。最后一个计划成功也不能遮住较早计划中仍失效的成果。

右侧任务面板显示“成果版本有效”“成果已失效，需重新验收”“已由新阶段替代”，并显示依赖名称和原因。重新启动或恢复任务时重新核对文件，不重复执行已完成的文件写入。

这张依赖图覆盖同一 Run 中当前用户任务的多个委派计划；真正的新一轮用户任务开启新的追踪范围，运行中追加指令和自动修复反馈不会清空当前关系。关系需要显式声明，尚不自动推断未声明的代码语义依赖，也不跨 Run 追踪。失效检查在执行边界进行；任务闲置时的面板仍是上次保存的状态，没有后台持续文件监听。执行阶段仍受每用户任务 12 阶段预算约束。

## 验证

`test/pawNext.test.ts` 使用离线模型和本机 HTTP 测试服务，覆盖 V3 多轮续聊、审批允许/拒绝、子 Agent 事件、子 Agent 写入审批、停止操作与真实宿主 JSON 流协议，另覆盖显式清空、空历史续接、首轮/后续工作段的索引恢复、模型绑定变化、差异投影和 Electron 请求参数，不调用付费模型。另有运行中追加输入的新建/续聊测试、重复输入 ID 与冲突校验、单子任务取消且兄弟任务继续的测试；交互 reducer 验证追加策略的历史兼容性、消费次数和预算边界。

附件验证覆盖格式/大小限制、首轮与续聊、图片模型输入和携带附件的重复投递；任务测试覆盖真实委派依赖阻塞与子任务文件证据；后台测试启动本地进程，验证日志、按 Run 隔离的停止和结束快照，并验证界面预览不会吞掉 Agent 的输出。

环境验收测试使用离线模型和真实本地文件，覆盖成功读取后通过、空口声称成功、越权写入拒绝、修复后复验、证据变化、超时、历史策略兼容，以及验收开始后进程退出的租约到期恢复。协议测试验证验收证据必须与对应候选和审计员身份绑定。
